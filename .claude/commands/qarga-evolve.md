Run controlled system evolution for `$ARGUMENTS`.

1. Read task review, performance scorecards, learning review, project-memory review, telemetry summary, system evals, and the relevant current files.
2. Require repeated/strong evidence; do not promote one anecdote into a permanent rule.
3. Delegate read-only diagnosis to `qarga-system-researcher` and require alternatives in the order documentation → checklist → skill → routing/command → tests/evals → hook/tool → prompt → integration → new agent.
4. Present the smallest reversible proposal, expected benefit, context/token cost, security/maintenance risks, rollback, required reviewers, and pilot to the project owner.
5. Do not implement until the project owner gives explicit approval for the proposed change.
6. After approval, delegate implementation only to `qarga-system-improver` under a completion contract.
7. Delegate independent review to `qarga-system-reviewer`; run validation, deterministic tests, security scan, system health, and fresh-context regression scenarios.
8. Run the policy-defined pilot and present KEEP / REVISE / REVERT. Permanent KEEP requires the approvals defined in `.claude/evolution/policy.json`.
