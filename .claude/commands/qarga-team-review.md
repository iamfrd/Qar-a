---
description: Analyze Qarğa capability gaps, over-broad roles, and future staffing needs
argument-hint: [milestone or scope]
---

Run an organizational review for `$ARGUMENTS`. Source-code changes are not required.

1. Read `.claude/capability-registry.json`, `.claude/project-memory/review.json`, recent plans, Git history, performance/learning signals, and completed tasks.
2. Look for evidence that the same capability gap has repeated, including concentrated technical-debt ownership, recurring ownerless liabilities, or experiment/decision work that repeatedly falls outside current roles.
3. For every gap, compare an existing agent, new skill, command/hook, MCP/plugin, and new-agent alternatives.
4. Propose a new agent only when separate context, recurring ownership, and different minimum permissions are required.
5. In a hiring proposal, include benefit, risk, coordination/token cost, scope, tools, reviewer, source basis, and success criteria.
6. Do not create an agent file without explicit project-owner approval.
7. Respect the priority order: technical completion, revenue/payment model, support operations, then marketing readiness.
